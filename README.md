# D.I. Recruitment

Next.js, TypeScript, Prisma, and MySQL recruitment website with an authenticated admin area.

## Production preparation

See `deploy/PRODUCTION.md` for staging/launch gates, persistent storage, backups,
baseline migrations and Linux Nginx/systemd templates. Run
`npx tsx scripts/check-production.ts` against a local or staging server to verify
rate limits, headers, footer links, health checks and application validation.
The templates still require your real domain, TLS, server secrets and operator testing.

## Styling and social configuration

Tailwind CSS 4 is integrated through `@tailwindcss/postcss`. The new social footer
uses prefixed utilities such as `tw:flex` and `tw:hover:bg-white/15`.
`app/tailwind.css` intentionally omits Preflight to preserve the existing design;
legacy custom CSS remains in use. This is an incremental integration, not a full CSS rewrite.

Facebook uses `FACEBOOK_PAGE_URL`. Set `LINKEDIN_URL`, `YOUTUBE_URL`, and
`TIKTOK_URL` to verified HTTPS agency profiles, then restart the server.
Unconfigured profiles show disabled labels rather than guessed account links.
The Facebook iframe loads lazily; errors originating inside Facebook cannot be
fixed by changing this site's code.

## Run locally

1. Start MySQL in XAMPP.
2. Install dependencies with `npm install`.
3. Copy `.env.example` to `.env` if no environment file exists.
4. Configure `DATABASE_URL`, a random `AUTH_SECRET` of at least 32 characters,
   `ADMIN_EMAIL`, and a strong `ADMIN_PASSWORD`.
5. Run `npm run db:push`, then `npm run db:seed` for initial setup.
6. Run `npm run dev -- --port 3001`.

Open http://localhost:3001 and sign in at /admin/login.
Seeding creates sample jobs and the initial admin account. It does not overwrite an existing admin password.
Do not run the seed just to add gallery albums.

## Event gallery

- Public gallery: `/gallery`; each published album has its own URL.
- Admin: `/admin/gallery`.
- Create a folder for each event, then upload its photos and videos.
- Upload up to 20 files per batch. Photos: JPG, PNG, WebP, under 1 MB each.
  Videos: MP4 or WebM, under 15 MB each.
- Add captions and display order for each file. The first photo in display order
  is used as the album cover.
- Open **Edit folder settings** and enable **Publish this album** when ready.
- Draft albums and their media are available only to signed-in admins.
- Deleting a file or folder permanently removes its database records and stored files.

Files are stored in `storage/gallery` by default, outside the public directory.
MySQL stores album names, file references, captions, and ordering.
The media route checks visibility before streaming a file and supports byte ranges
for video seeking. Filenames are generated by the server; original filenames are
kept only for display.

## Password changes and team photos

- Open `/admin/settings` to change your password. Enter the current password and a
  new password of 12–128 characters, then confirm it. Other sessions are invalidated.
- The initial `ADMIN_PASSWORD` in `.env` is only used to create a new account.
  Changing the password does not expose it in the environment file.
- Open `/admin/team` to add or edit a team member. Upload a JPG, PNG, or WebP photo
  under 1 MB; no photo URL is required. Existing photos can be replaced or removed.
- Team photos are checked, resized, and saved as WebP in `storage/team`.
  Set `TEAM_STORAGE_DIR` for a persistent disk on a production server.
- Replacing/deleting a portrait removes the old stored file. Hidden profiles' photos
  are only accessible to signed-in admins.
- All photo uploads reject files of 1,048,576 bytes or more, and gallery videos
  reject files of 15,728,640 bytes or more.

## Code organization

### Public homepage and dashboard Facebook feed

The public homepage (`/#facebook`) and admin overview embed D.I. Recruitment's public Facebook Page timeline using
Meta's Page Plugin. Posts are loaded by Facebook when the feed opens; use
**Refresh feed** to reload it without leaving the dashboard. This does not import
posts into MySQL or publish anything to Facebook.

Set `FACEBOOK_PAGE_URL` in `.env` to change the source page, then restart the app.
The default is the Facebook Page linked from the reference agency website.
This requires a public Facebook Page without age/country restrictions; personal
profiles and restricted posts are not supported. Browser privacy settings or
Facebook sign-in requirements may prevent the embedded timeline from appearing.
The direct Facebook link remains available in those cases.

Official documentation: https://developers.facebook.com/documentation/plugins/page-plugin

### Source folders

- `app/gallery`: public album listing and event pages.
- `app/admin/gallery`: protected album pages and server actions.
- `components/gallery-admin.tsx`: album forms, uploader, and media editing controls.
- `components/gallery-media.tsx`: filters and accessible photo preview.
- `app/api/admin/gallery/[id]/media`: authenticated file upload endpoint.
- `app/api/gallery/media/[id]`: authorized file streaming.
- `lib/gallery-storage.ts`: file validation and disk storage.
- `prisma/schema.prisma`: database models and relations.

Run `npm run format` to format source files. Run `npm run format:check` and
`npm run lint` to check formatting and TypeScript. Source comments explain
authorization, storage boundaries, cache updates, and other non-obvious behavior.

## Hosting

### Blog, job, legal document, and leadership images

Admins can upload JPG, PNG, or WebP images strictly under 1 MB. Blog and job
editors support previewing, replacing, and removing images. Legal documents now
use image uploads instead of URL entry; existing document links remain available
until replaced. Published document thumbnails open the full image in a new tab.

Use **Admin → About pages** to edit the Chairman and Managing Director messages,
including their portraits. Both messages appear in the public About menu.

Images are decoded, normalized, and stored as WebP in `storage/content`.
Set `CONTENT_IMAGE_STORAGE_DIR` to a persistent absolute path in production and
back it up with MySQL. Draft blog/job/document images require admin authentication.
Apply schema additions with `npm run db:push` before starting an existing install.
Run `node scripts/check-content-images.mjs` against the local server to verify uploads,
size/type validation, draft privacy, publishing, replacement, and image removal.

Build with `npm run build` and run with `npm start`. Stop the development server
before rebuilding on Windows so Prisma's engine is not locked.

Gallery uploads require a Node.js host with a persistent writable disk. Set
`GALLERY_STORAGE_DIR` to that disk's absolute path and back it up together with
MySQL. An ephemeral/serverless filesystem is not suitable for this storage
implementation; use persistent hosting or replace the storage adapter with object
storage before deploying there. If using multiple server instances, they must share
the upload directories. Configure the reverse proxy's request limit to allow 16 MB
(15 MB video limit plus multipart overhead). Back up both gallery and team photos.
Serve the production app over HTTPS for secure admin cookies.

The website is configured locally; no public deployment is performed by setup.
